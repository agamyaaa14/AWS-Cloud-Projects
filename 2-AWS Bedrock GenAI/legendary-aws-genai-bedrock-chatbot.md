## Introducing Today's Project

In this project, I'm going to build a Python chatbot using AWS CloudShell and Amazon Bedrock’s Converse API, which can chat with a foundation model and maintain conversation history.

I want to learn this because I wanted to understand how real AI applications connect to large language models through APIs instead of training models from scratch.

### Key tools and concepts

The key tools I used include Amazon Bedrock, AWS CloudShell, and Bedrock Guardrails.

Key concepts I learnt include how to connect Python code to foundation models using APIs, how inference works, and how to manage AI interactions using the CLI instead of a UI.

### Challenges and wins

This project took me approximately 1.5 hours.

The most challenging part was working in CloudShell without a mouse, which made navigation and editing slower, but it helped me get comfortable with command-line usage.

### Understanding Foundation Models

I learned that a foundation model is a large pre-trained AI model that can perform multiple tasks without needing to be trained again.

Instead of building a model from scratch, we can use these models through APIs, which saves time and cost. Amazon Bedrock gives access to multiple models and handles all the infrastructure, so we only focus on using the model.

## Writing My First AI API Call

In this step, I'm going to use CloudShell to write a Python script that calls the Bedrock Converse API and generates a response from the model.


![Image](http://learn.nextwork.org/happy_azure_swift_duck/uploads/aws-genai-bedrock-chatbot_m4r9w2t6)

### Understanding the Converse API

I used boto3.client() which is the official AWS Python SDK, allowing my script to communicate with Bedrock.

The messages list contains the prompt, where each message has a role (like user) and content (the actual text). This structure helps the model understand the conversation.

## Building a Multi-Turn Chatbot

In this step, I am building a chatbot that can maintain conversation history and respond across multiple turns.

Conversation history is important because it helps the model understand context and give more relevant responses.

### System Prompt and Inference Parameters

I configured a system prompt to give the chatbot a specific role (like a friendly tutor), which changes how it responds.

I also adjusted inference parameters:
Temperature – controls how creative or predictable the response is
TopP – controls how diverse the output is
MaxTokens – limits the length of the response

This helped me understand how we can control model behavior without changing the model itself.

## Adding Guardrails for Responsible AI

In this project extension, I'm adding Guardrails to my API calls to make sure the chatbot follows safe and responsible behavior.

Guardrails allow us to filter harmful or sensitive content automatically without writing custom logic in code.
This is important because in real applications, AI responses must be safe and controlled.

![Image](http://learn.nextwork.org/happy_azure_swift_duck/uploads/aws-genai-bedrock-chatbot_s6n3p9w1)

### Testing Content Safety

I tested the guardrail by asking the chatbot to generate harmful content.

The model refused to respond and gave a safe, responsible reply instead, which confirmed that the guardrails were working correctly.
